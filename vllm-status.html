2 Mock vLLM Server — Testing Without GPU

We built a mock vLLM server (scripts/mock-vllm-server.py) that mimics the OpenAI-compatible /v1/chat/completions API. This lets us test the Go LLMDrafter client without a GPU — the mock returns a pre-written bid response, and the Go client processes it identically to a real LLM response.

How it works

1. Start the mock server: python3 scripts/mock-vllm-server.py --port 8001
2. Run the bid-drafter with the mock endpoint: ./bid-drafter --once --vllm-endpoint http://localhost:8001/v1
3. The Go client calls the mock, gets a bid response, processes it — identical to a real vLLM call.

3 The 3-Tier Fallback Chain

The Go LLMDrafter client has a 3-tier quality ladder — it's always available, even without a GPU:

TierSourceQualityAvailability
1 (primary)Local vLLM serving fine-tuned Qwen 2.5 72BBest — natural, context-aware, fine-tuned on Cascadia corpusRequires GPU
2 (fallback)Anthropic Claude Sonnet 4.5 (via API)Good — general-purpose LLM, not Cascadia-specificAlways (with API key)
3 (always)TemplateDrafter (Go text/template)Basic — formulaic but always availableAlways

The Go client tries tier 1 first. If unreachable, falls to tier 2. If both fail, falls to tier 3. The bid-drafter is never unavailable — it degrades gracefully.
