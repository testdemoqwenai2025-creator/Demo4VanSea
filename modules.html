1 The Four Core Feature Modules

The Cascadia OS surface is composed of four product modules. Each module maps to a user type, exercises the regional moat, and is built on the data mesh + event-driven architecture. Module B is the Year-1 wedge; Modules A, C, D are Phase 2 horizontal expansion.

2 Module Sequencing Rationale

The ordering is not arbitrary — Module B is the wedge because it exercises the regional moat (USMCA + Indigenous + CCA) directly, compounds the compliance knowledge graph, and serves a daily-pain user type. Modules A, C, D are Phase 2 horizontal expansion that depend on the wedge's user base to validate their own daily-pain hypotheses.

The hard pivot point

If the wedge doesn't hit 500 DAU by Month 9, pivot to a deeper vertical (e.g., focus only on CCA-exposed industries in WA) before expanding horizontally. Don't build Modules A, C, D until Module B has validated daily-active usage.

3 The Wedge's Critical Refinement — Match Confidence, Not Win Probability

Reframing

The user's blueprint says "85%+ win probability." This overpromises. The AI cannot predict win probability because it cannot see (a) the user's bid quality, (b) competitor pricing, (c) relationship capital with the contracting officer. The AI can predict match confidence: how well the tender's NAICS, size standard, geography, set-aside flags, and capability requirements align with the user's declared capability statement. More honest, more defensible against liability if a bid loses, more aligned with the algorithmic-transparency principle.

The daily digest format becomes: "3 new tenders match your capability statement at 85%+ match confidence. [Tender A: 92% — your NAICS 238210 matches; supply-chain profile 65% US content satisfies USMCA threshold; CCA exposure $42K claimable]. [Tender B: 88% — ...]. [Tender C: 85% — ...]."

4 The Bloomberg-Style <GO> Syntax

Module A's Command Palette UI uses Bloomberg-Terminal-style keyboard shortcuts: AAPL <GO> for Apple market data, LUMBER FUTURES <GO> for the lumber futures chain, tender 2026-Q4-0142 <GO> to open a tender.

Critical refinement — accept both shortcut AND natural language

The parser accepts both AAPL <GO> AND show me Apple stock. Power users type the shortcut; new users type the question. The parser dispatches to the same handler. This eliminates the "Terminal is too complex" adoption risk without sacrificing the power-user experience.

5 Algorithmic Transparency — The "Why?" Button

Every AI recommendation has an Explainability Dashboard. The user clicks "Why?" and sees the exact weighted factors, the evidence chain for each factor, and the provenance anchor (the SHA-256 hash that proves the recommendation was made on this specific date with this specific reasoning — anchored to a public blockchain).
