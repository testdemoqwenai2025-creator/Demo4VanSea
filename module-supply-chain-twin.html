Module C — Physical-Digital Supply Chain Twin

Live geospatial map of the I-5 / Highway 99 corridor. Multi-tier supplier graph with propagation alerts. Dynamic Scope 3 carbon ledger per route.

Phase 2LogisticsWASM mapCarbon ledger

1 Purpose

Provide a live, geospatial, multi-tier digital twin of the Cascadia supply chain corridor. The user sees: where their goods are, where their suppliers' suppliers are, where the disruptions are, and what the carbon impact is.

2 Key Features

2.1 Corridor Geospatial Map

An interactive, real-time map of the I-5 / Highway 99 / Trans-Canada Highway 1 corridor. Overlays include:

  • Live border wait times — Pacific Highway, Peace Arch, Lynden, Sumas crossings (CBSA + WSDOT APIs)
  • Port of Vancouver / Seattle / Tacoma berth occupancy and crane availability — USACE + port-authority feeds
  • Rail schedules — BNSF, CN, CPKC (public track warrant data)
  • Weather overlays — wildfire smoke (NASA FIRMS), atmospheric river forecasts (NOAA AR Alerts), flood watches (NWS)
  • Construction closures — WSDOT, BC MoTI
Why WebAssembly (WASM)

The map must render 10,000+ live positions (vessels, trucks, rail cars) at 60fps. JS libraries (D3, deck.gl) struggle past 100k DOM elements; WASM (Rust + WebGPU) handles millions. Be selective — WASM is overkill for 90% of the UI. Commit to WASM for 3 specific surfaces: (1) supply-chain graph viz, (2) port/logistics map, (3) carbon-ledger route optimizer.

2.2 Multi-Tier Supplier Graph

A Neo4j (or Apache Age — Postgres-native graph extension that uses Cypher) visualization showing Tier 1, Tier 2, Tier 3 suppliers. Click a node to see the supplier's profile, click an edge to see the relationship (contract value, lead time, dependency type).

Killer feature — propagation alerts

If a sub-supplier (Tier 2 or Tier 3) is hit by a disruption (strike, fire, regulatory shutdown, earthquake), the OS propagates the impact up the graph and alerts the Tier 1 manufacturer: "Your widget supplier's Tier 2 steel provider is in a strike zone. Affected contracts: 3. Estimated impact: 4-week delay on Contract #ABC123."

Refinement — supplier data sovereignty

Implement a consent layer: each supplier in the graph controls how many tiers DOWN they consent to expose. Default is Tier 1 only (the user sees their direct suppliers). Tier 2 exposure requires explicit per-supplier consent. This is the data sovereignty principle applied at the supplier-graph layer.

2.3 Dynamic Carbon Ledger

Automatically calculates the Scope 3 emissions of a specific logistics route, factoring in:

  • Grid carbon intensity — BC Hydro: 11.4 gCO2/kWh (hydro-dominant); WA grid: 191 gCO2/kWh (mixed); OR grid: 235 gCO2/kWh (coal + natural gas)
  • Mode of transport — diesel truck, rail, marine vessel (each with different gCO2/tonne-km)
  • Origin and destination — route distance
  • CCA compliance cost — if WA-grid-powered, applies the CCA allowance price
  • BC carbon tax cost — if BC operations, applies the carbon tax

The ledger is per-route, per-shipment. Exported as CSV for the user's own ESG reporting. Every calculation is hash-anchored in the provenance ledger so the user's ESG report is auditable.

Refinement — calculate avoided emissions too

If the user reroutes from truck to rail, how much carbon did they avoid? This is the metric ESG-conscious shippers care about, and it's a moat — competitors without the live grid-carbon-intensity data can't compute it.
