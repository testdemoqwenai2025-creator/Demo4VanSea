Roadmap — Wedge → Canonical

Wedge → horizontal → platform → federation → canonical reference. Five phases over 20 years, with explicit success criteria for graduating each phase.

5 phases20-year horizonQuarterly review

1 Five-Phase Trajectory

The roadmap is organized into five phases. Each phase has a primary objective, a small number of modules built or extended, and explicit success criteria for graduating to the next phase.

2 Phase 1 — The Wedge (Year 1)

Objective: Establish daily-active usage by one user type (procurement officers in Cascadia mid-sized contractors) via a single wedge feature: automated cross-border tender compliance matching.

ModuleOwns
tendersNormalized tender records from SAM.gov, BC Bid, WA Commerce, OR Buys
regulationsUSMCA, RCW, ORS, BC statutes, WAC, OAR — full-text indexed
complianceThe Compliance Reasoner — eligibility, USMCA, Indigenous, CCA exposure
usersProfiles, saved searches, watchlists, supply-chain declarations
bidsThe Bid Drafter — drafts with provenance footnotes
provenanceAppend-only ledger with monthly blockchain anchor
Success criteria (graduation to Phase 2)

500 DAU · 5K weekly assessments · 200 monthly bid drafts · 15% win-rate uplift · $400K MRR · 50K provenance records/week · ≥1 Indigenous-nation partnership established

3 Phase 2 — Horizontal Expansion (Years 2–3)

Objective: Expand from one user type to four (procurement officers, logistics managers, investors, policy analysts) by adding the modules each type needs.

Success criteria

3K DAU across 4 user types · $1–2M ARR · 5M provenance records / 60 anchor blocks · 5 Indigenous-nation partnerships · conversational interface prototype

4 Phase 3 — Platform Maturity (Years 4–7)

Objective: Transition from vertical product to horizontal platform by opening the OS to third-party module authors and government integration.

Modules added: third_party_modules (community-contributed agent catalog), open_api (public embedding API). Conversational interface becomes primary for 30%+ of interactions.

Strategic activities: at least one state/provincial government procurement mandate for "AIBizVan-OS-compatible" data formats; 30+ Indigenous-nation partnerships across Cascadia; 50+ contributed third-party modules.

Success criteria

10K DAU · $5–10M ARR · 50M provenance records / 120 anchor blocks · first sibling-region OS (Salmon Nation) operational

5 Phase 4 — Federation (Years 8–12)

Objective: Federate the OS template to sibling regions. Cascadia remains the anchor; siblings operate independently with shared infrastructure.

Sibling regions (prioritized):

  • Salmon Nation OS — Pacific Northwest coast bioregion (extending Cascadia northward to Alaska, southward to N. California). Most aligned.
  • Great Lakes OS — Chicago / Detroit / Toronto / Cleveland corridor.
  • Gulf of Mexico OS — Houston / New Orleans / Tampa / Veracruz corridor.
  • Northeast Corridor OS — Boston / NYC / Philadelphia / DC.
Success criteria

3+ federated regional OSes · 50K DAU across federation · $15–25M ARR · 250M provenance records / 180 anchor blocks · 30+ Indigenous nations partnered across federation

6 Phase 5 — Canonical Reference (Years 13–20)

Objective: Federated OSes operate as the canonical reference for regional economic intelligence. Government procurement, Indigenous-nation governance, and major industry consortia reference "AIBizVan-OS-compatible" as a standard.

Indicative milestones: 5+ federated regional OSes · 100+ Indigenous nations partnered · 1B+ provenance records / 240 anchor blocks (cannot be backdated) · 50+ cities with CIRS 5.0 (causal inference) · quantum-resilient signing · conversational primary interface · edge-deployable agent runtimes · 3–5 humans + 15–20 agents per regional OS · $30–50M ARR.

7 Decision Tree for New Modules

Every new module idea is evaluated against this decision tree before being committed:

#QuestionIf no
1Serves one of the existing user types or opens a new user type?Defer
2Is the pain acute and recurring for that user type?Defer
3Is the data available, consented, and provenance-backable?Defer until it is
4Does it compound the moat — does using it make the OS harder to replicate?Defer
5Does it require cross-domain writes or shared schemas?Defer until refactored
6Can it be built as a new domain without touching existing domains?Refactor first
